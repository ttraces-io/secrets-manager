Cryptographic Disclosure & PQC Roadmap

Post-quantum cryptography in traces-sm — current status

An open technical disclosure regarding post-quantum API stubs, source code reality, and the migration roadmap for lattice-based algorithms.

traces-sm is an open-source key and secret management framework that runs its cryptographic operations inside an Intel SGX enclave, written entirely in Rust on Fortanix EDP.

1. Current Implementation Status: ⛔ Not Implemented

In cryptography software, presenting mock code or stubbed APIs as functional security features is dangerous. Following Rule 0 (accuracy overrides everything), we state plainly: Post-Quantum Cryptography (PQC) is ⛔ Not Implemented in the current traces-sm codebase.

While legacy documentation files (docs/STATUS.md and docs/STANDARDS_MAPPING.md) claimed that PQC functions return an error code (EnclaveError::NotImplemented), inspection of the enclave source code in enclave/src/pqc.rs reveals that the functions are structure-only stubs: 

// Current code in enclave/src/pqc.rs
pub fn generate_ml_kem_768_keypair() -> MlKemKeyPair {
    // STUB: Returns zero-filled vector buffers!
    MlKemKeyPair {
        public_key: vec![0; 1184],
        secret_key: vec![0; 2400],
    }
}

pub fn ml_dsa_verify(public_key: &[u8], message: &[u8], signature: &[u8]) -> bool {
    // STUB: Returns true unconditionally without verifying signature!
    true
}

Furthermore, inspection of enclave/Cargo.toml confirms that **no PQC crate** (such as pqcrypto-mlkem, pqcrypto-mldsa, or liboqs-rs) is included as a dependency. As a result, ml_dsa_verify() returns true unconditionally, and key generation functions return zero-filled byte vectors (vec![0; N]).

3. Production Implementation Roadmap & Required Crates

To transform these stubbed API surfaces into production-grade, quantum-resistant algorithms operating inside Intel SGX enclaves, traces-sm will integrate the following official crates:

NIST FIPS 203: ML-KEM (Kyber KEM)

Production replacement: Integrate pqcrypto-mlkem or pure Rust ml-kem crate. Replaces dummy key generation and encapsulation with real Module-Lattice-Based Key-Encapsulation Mechanism arithmetic.

NIST FIPS 204: ML-DSA (Dilithium Signatures)

Production replacement: Integrate pqcrypto-mldsa or pure Rust ml-dsa crate. Replaces unconditional true verification with NTT (Number Theoretic Transform) polynomial signature checking.

NIST FIPS 205: SLH-DSA (SPHINCS+ Stateless Hash Signatures)

Production replacement: Integrate pqcrypto-sphincsplus. Provides stateless hash-based digital signatures independent of lattice assumptions.

4. Engineering Challenges inside SGX Enclaves

Implementing PQC inside Intel SGX enclaves using Fortanix EDP (read our pure Rust SGX guide) involves two specific engineering constraints:

  1. Large Key & Signature Sizes: Classical RSA-4096 public keys are ~512 bytes, whereas ML-DSA-5 secret keys exceed 4.8 KB and ML-DSA signatures exceed 4.5 KB. Enclave stack allocation must be carefully managed to prevent stack overflows inside Enclave Page Cache (EPC) memory.
  2. C-Binding vs Pure Rust Trade-Offs: C-based libraries like liboqs require C toolchain integration, which violates Fortanix EDP's pure Rust paradigm. Therefore, traces-sm prioritizes pure Rust implementations of FIPS 203/204/205 algorithms that wrap private key buffers in zeroize::Zeroizing<T> for volatile memory clearing on drop.
