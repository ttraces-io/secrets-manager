NIST Standards & CMVP Disclosure

FIPS 140-3 alignment, and why traces-sm is not FIPS validated

An open, transparent evaluation of cryptographic compliance terminology, implementation standards, and certification reality.

traces-sm is an open-source key and secret management framework that runs its cryptographic operations inside an Intel SGX enclave, written entirely in Rust on Fortanix EDP.

1. Understanding "FIPS Compliant" vs "NIST CMVP Validated"

In security engineering, software vendors frequently misuse terms like "FIPS compliant", "FIPS certified", or "validated". To maintain technical integrity, users must understand the exact regulatory boundary between software design alignment and government certification:

FIPS 140-3 Design Aligned

Software is engineered to conform to FIPS specifications in source code. This includes implementing FIPS-approved algorithms (AES-256-GCM, ECDSA P-256, HMAC-SHA256), following NIST SP 800-90A DRBG guidelines, and enforcing volatile memory zeroization on key drop. traces-sm is FIPS design aligned.

NIST CMVP Validated (Certified)

A specific compiled software binary and physical hardware boundary has undergone formal testing by an accredited NVLAP laboratory and received an official certificate number from the NIST Cryptographic Module Validation Program (CMVP). traces-sm holds NO NIST CMVP certificate.

Formal Compliance Disclaimer

traces-sm holds no NIST CMVP certificate number and has not been independently audited by a third-party security firm or NVLAP laboratory.

Statements in legacy documentation claiming "100% CONFORMANT" or "certified" are inaccurate. While traces-sm source code implements NIST algorithm specifications inside Intel SGX enclaves, it does not possess a CMVP validation certificate. Regulated enterprise environments requiring mandatory FIPS 140-2/140-3 certificate numbers for FedRAMP or FISMA compliance should evaluate this distinction carefully (compare against HashiCorp Vault).

4. FIPS 140-3 Key Zeroization Requirements

Section 7.9 of FIPS 140-3 specifies that a cryptographic module must provide zeroization mechanisms to overwrite all plaintext secret keys, intermediate key values, and critical security parameters (CSPs) before memory is returned to the system pool.

In traces-sm, zeroization is enforced using Rust's type system and volatile memory barriers. Every sensitive key vector inside the enclave is wrapped in zeroize::Zeroizing<T>. 5. Frequently Asked Questions

What is the difference between FIPS compliant and FIPS certified?

FIPS compliant (or FIPS design aligned) means software implements FIPS algorithm specifications and memory zeroization patterns. FIPS certified (or CMVP validated) means the specific software binary and hardware boundary has received an official NIST CMVP certificate number. traces-sm follows FIPS 140-3 design patterns but holds no NIST CMVP certificate number and has not been independently audited.
